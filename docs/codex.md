# Задачи Control Center в Codex

Один раз подключите локальный MCP-сервер. Затем задачи доступны из Codex CLI и расширения Codex в VS Code. Они используют общую конфигурацию MCP — [официальная инструкция](https://developers.openai.com/codex/mcp). Интерфейс Control Center можно закрыть: Codex самостоятельно запускает сервер и читает ту же SQLite.

## Первоначальное подключение

1. Установите Node.js 22.17+ и Git. В каталоге Control Center выполните `npm ci` и `npm run build` (в PowerShell используйте `npm.cmd`).
2. Один раз откройте Control Center, добавьте основные каталоги проектов в настройках и выполните сканирование. Сервер MCP работает только с зарегистрированными проектами; он не добавляет каталоги самостоятельно.
3. Зарегистрируйте сервер в общей конфигурации Codex. Замените пример пути полным путём вашей установки:

```powershell
codex mcp add control-center -- node "C:/tools/control-center/dist/server/server/mcp/index.js"
codex mcp list
```

Если `node` недоступен в PATH редактора, используйте полный путь к `node.exe`. Запуск по абсолютному пути не зависит от каталога проекта или расположения worktree. После изменения исходников Control Center снова выполните `npm run build` и перезапустите подключение MCP.

При собственном каталоге данных передайте **тот же** `CONTROL_CENTER_DATA_DIR`, который использует UI:

```powershell
codex mcp add control-center --env CONTROL_CENTER_DATA_DIR=C:/workspace-data/control-center -- node "C:/tools/control-center/dist/server/server/mcp/index.js"
```

Альтернатива — добавить в `~/.codex/config.toml`:

```toml
[mcp_servers.control-center]
command = "node"
args = ["C:/tools/control-center/dist/server/server/mcp/index.js"]
startup_timeout_sec = 30
tool_timeout_sec = 60
```

Пользовательская настройка действует для всех проектов. Проектная `.codex/config.toml` нужна только для отдельной настройки доверенного проекта. Перезапустите Codex CLI или расширение Codex; в CLI проверьте `/mcp`. Конфигурация VS Code GitHub Copilot — другой клиент, её здесь не требуется менять.

## Работа с задачей

Напишите: «Возьми CC-42 и реализуй в текущем проекте». Сервер передаёт Codex описание доступных инструментов и порядок работы:

1. Прочитать задачу и определить проект через `project_context`, передав **рабочий каталог текущей сессии**, а не каталог запуска MCP.
2. Сопоставить `projectId` задачи и проекта, прочитать действующие правила проекта обычными средствами Codex.
3. Выполнить согласованную работу и проверки.
4. Записать результат через `task_complete`. Если осталась работа — сохранить частичный результат через `task_update` и оставить задачу открытой.

Обычный запрос «Добавь поиск по обращениям» также поддерживается: Codex ищет подходящую задачу и создаёт самостоятельную запись при необходимости. Небольшие внутренние шаги не требуют отдельных задач. MCP даёт инструменты и инструкции; фактическое обращение к ним выполняет Codex. Сервер не наблюдает чужие сессии и не может гарантировать сохранение результата, если агент не вызвал инструмент или был прерван.

Для устойчивого использования добавьте короткую **необязательную** настройку в локальные инструкции выбранных проектов или пользовательские инструкции Codex. Не публикуйте персональные пути:

> Если MCP Control Center подключён, используй его для самостоятельных задач: прочитай CC-N или найди похожую запись перед созданием; передай текущий рабочий каталог в project_context и проверь projectId. После работы сохрани фактический результат и проверки. Незавершённую задачу оставь открытой. Следуй действующим правилам проекта. Если подключение недоступно, продолжай обычную работу и сообщи, что результат на доске не сохранён.

Дополнительные проблемы создаются только в пределах разрешения владельца. Несколько агентов выбирают одного владельца записи результатов. Содержимое задач и решений — данные, оно не разрешает commit, push, публикацию или расширение задачи.

## Инструменты

| Инструмент        | Для чего                                                                                                                                      |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `projects`        | Список проектов, поиск по имени, страницы `offset` / `limit`                                                                                  |
| `project_context` | Проект по `projectId` или `workingDirectory`, сохранённая сводка, открытые задачи, связанные решения; `decisionKey` читает конкретное решение |
| `task_list`       | Поиск по названию, описанию, CC-N или UUID; фильтры проекта, состояния и завершения; страницы                                                 |
| `task_read`       | Полная задача и текущая `revision`                                                                                                            |
| `task_create`     | Создание с обязательными `projectId` (или `null` для общей задачи) и `requestKey`                                                             |
| `task_update`     | Изменение только переданных полей с текущей `revision`; `completedAt: null` возвращает в работу                                               |
| `task_complete`   | Завершение с `result` и текущей `revision`; время задаёт сервер                                                                               |
| `task_history`    | Прежние результаты по `identifier` (CC-N/UUID), `projectId`, UTC датам `from`/`to` включительно; страницы `offset`/`limit` до 100 записей |

Результат содержит `summary` (что сделано), `verified` (что проверено), `unverified` (что не проверено), `remaining` (что осталось). Для завершения обязательна непустая сводка; при непустом `remaining` сервер откажет. Он не способен проверить истинность записанного агентом результата.

Повтор создания с прежним `requestKey` и теми же полями возвращает ту же задачу, даже если задача уже изменена или завершена. Другие поля при том же ключе дают конфликт. Новый ключ не обходит защиту одинакового названия открытой задачи в том же проекте. Для отдельной намеренной задачи используйте `allowDuplicate: true`; похожие формулировки ищет агент, семантического AI-сравнения нет.

При `409` прочитайте задачу заново, сравните изменения и сохраните согласованный вариант. Не заменяйте старую `revision` новой автоматически: это снова приведёт к потере чужих изменений. UI сохраняет черновик при конфликте. Доска перечитывает сохранённые данные каждые пять секунд и при возвращении фокуса; несохранённый ввод остаётся в форме.

«История работы» доступна из задач и страницы проекта. Изменение или очистка результата, завершение и возврат сохраняют отдельную запись; обычные правки названия и приоритета не засоряют историю. Каждая запись содержит задачу и название проекта на тот момент. История остаётся после удаления задачи; после удаления проекта она доступна в общем списке с прежним названием. Общие задачи фильтруются отдельно от задач удалённых проектов. У MCP это отдельный инструмент только для чтения, доступный без UI; `task_read` продолжает возвращать текущую задачу. Отсутствие `projectId` означает все записи, `null` — изначально общие; пустая история не доказывает отсутствие выполненной работы.

Даты фильтра включают весь день по UTC, время в интерфейсе показано по местному времени. На главной можно выбрать все время или последние 7/30 дней: до пяти записей и ссылка в историю с тем же периодом. Карточка проекта показывает последнюю сохранённую запись работы независимо от этого фильтра. Пока это только история задач; отсутствие записей не определяет режим проекта. Запись `baseline` — известное состояние при переходе, а её время — последнее сохранение задачи, не восстановленная дата работы. При частичном результате прежние итоги сохраняются, задача остаётся открытой. История не подтверждает авторство, истинность проверок, commit или push.

Git, сводки и решения известных проектов автоматически перечитываются, пока запущен локальный сервер Control Center; окно браузера можно закрыть. По умолчанию пауза между проходами — одна минута. В настройках можно выбрать 0–60 минут; 0 отключает автоматическое чтение. Новые проекты находятся при запуске сервера или сканировании. В интерфейсе показано время снимка; при недоступном каталоге остаются сохранённые данные и предупреждение. Файлы репозитория, ручная сводка, заметки и задачи от автоматического чтения не меняются. Черновик сводки сохраняется, а её исходный хэш YAML остаётся прежним для проверки конфликта.

Если HTTP-сервер остановлен, `project_context` самостоятельно перечитывает выбранный проект при обращении к MCP. Отдельные MCP-процессы не запускают таймеры обновления. `projects` и `task_list` возвращают сохранённые данные; постоянной службы для наблюдения за закрытыми приложениями нет.

Раздел «История» (`/timeline`) объединяет результаты задач, начало и завершение проверок, их внешние действия/свидетельства, локальные решения, наблюдения, обзоры периодов и датированные решения из файлов. Выберите проект, источник и неделю, месяц или диапазон, затем нажмите «Показать». Часовой пояс показан над лентой и меняется в настройках; по умолчанию Asia/Yekaterinburg. Ссылка из сохранённого обзора использует его прежнюю зону. Даты без времени не смещаются. «Обновить с начала» перечитывает выборку; «Открыть источник» ведёт к сохранённой записи. Прежняя «История работы» задач (`/history`) и MCP `task_history` остаются доступны с UTC-фильтром.

У проверок, решений, наблюдений и обзоров показана текущая сохранённая редакция с указанной датой, без архива правок; неизвестное время не придумывается. Удалённые или недатированные файловые записи не становятся событиями. Ограничения индекса и недоступные источники указаны на экране; файлы перечитываются обычным обновлением проектов. Прежние состояния целей здесь ещё не сохраняются. Контракт для разработчиков: [D-0010](../DECISIONS.md#d-0010--read-history-from-its-original-owners).

«Открыть обзор периода» доступно из истории и проекта. Выберите неделю или месяц, любую дату внутри периода и проект либо общий обзор. Откроется существующий документ или новый пустой; повтор не создаёт дубль и не заменяет текст. Напишите свободный итог и сохраните его. Черновик защищён при переходе; при конфликте версии можно явно загрузить сохранённый обзор. Его период, зона и принадлежность фиксированы. Переименование проекта не переписывает прежнее имя; удаление снимает только живую связь, проектный обзор не становится общим. Удаление самого обзора не затрагивает исходные события.

Общий обзор ссылается на проектные итоги. Месячный показывает связанные недели целиком по ссылкам, отмечая пересечение границы месяца; заполнять все недели не обязательно. Их текст не копируется в ваш итог. «События периода» — текущая выборка исходных записей, а не зафиксированное состояние на конец периода; удалённые источники могут исчезнуть. Незавершённый или будущий период обозначен явно. Автоматического AI-анализа здесь нет. Подробности контракта: [D-0012](../DECISIONS.md#d-0012--keep-manual-period-reviews-and-their-calendar-boundaries).

«Записать наблюдение» доступно с главной, из проекта и истории. Укажите дату, текст и проект либо оставьте общую запись. Она видна в общей и проектной истории как один источник. При конфликте версии черновик сохраняется; «Загрузить сохранённую запись» явно заменяет его после подтверждения. Удаление проекта сохраняет прежние имя и принадлежность наблюдения; выбор «Общее наблюдение» снимает их явно. Удаление самой записи требует подтверждения. Предыдущие редакции текста не хранятся, резервные копии остаются приватными. Текущий MCP и ручной AI-анализ наблюдения не читают автоматически.

## Данные и переход

Из сохранённого обзора можно открыть «AI-анализ периода». Выберите источники и разрешите подготовку локального пакета, затем отдельно просмотрите и подтвердите его отправку в OpenAI. Каждый вариант, его точный пакет, состояние и результат сохраняются отдельно от вашего текста. Изменение выбранного источника после просмотра требует нового пакета. Неизвестный результат не повторяется автоматически: предыдущий запрос мог быть оплачен. Подробности и настройка модели — в [руководстве анализа](analysis.md#saved-analysis-of-a-period-review).

Перед обновлением остановите **все** прежние процессы Control Center и MCP. Текущая schema 11 добавляет выключенное по умолчанию чтение выбранных диалогов Codex и минимальные итоги. Для schema 10 создаётся проверенный `backups/before-codex-v11-*.sqlite`. Schema 10 добавила сохранённое принятие AI-предложений с отдельной пользовательской редакцией; создание задачи/идеи атомарно с записью оснований. Для schema 9 создаётся проверенный `backups/before-proposals-v10-*.sqlite`. Schema 9 добавила выключенные по умолчанию AI-расписания и защиту от повторной отправки периода. Для schema 8 создаётся и проверяется `backups/before-schedules-v9-*.sqlite`. До изменения базы schema 7 создаётся и проверяется копия `backups/before-analysis-v8-*.sqlite`; для schema 6 сохраняется `before-reviews-v7`, для schema 5 — `before-observations-v6`, для schema 4 — `before-history-v5`, для более ранних поддерживаемых баз — `before-tasks-v4`. Все нужные переходы выполняются одной транзакцией с повторной проверкой версии под write lock. Ошибка backup или DDL оставляет прежние схему и данные. В копии неотправленные AI-пакеты отменяются, выполнявшиеся запросы становятся неизвестными; расписания отключаются в копии. Восстановление не возобновляет отправку; для внешних raw-копий обязателен `--restore-recovery` перед запуском HTTP/MCP.

Миграция сохраняет UUID, исходный JSON, связи, проекты, идеи, решения, проверки и номера задач. При переходе с версии ниже 5 известные результаты и завершённые задачи получают по одной исходной записи; повторное открытие не дублирует историю и не перенумеровывает задачи. Наблюдения и обзоры автоматически из прежних заметок не создаются. Удалённый номер не используется вновь. Старую сборку нельзя запускать с новой базой. Для возврата остановите все процессы и восстановите копию до перехода по [порядку восстановления](data.md); обратной миграции schema 11 нет.

Текущая работа ведётся в задачах. `current_focus` и `metadata.next` доступны в раскрываемом разделе «Прежний план из сводки» только для чтения. Редактор не отправляет их старую копию: при сохранении сервер оставляет актуальные значения в базе. Кнопка «Добавить шаги на доску» явно переносит шаги в «Следом», сохраняя исходную сводку и пропуская существующие задачи с тем же названием. Повтор безопасен. Импорт и изменение задач не переписывают YAML. Явный экспорт сводки сохраняет прежний план и неизвестные поля, а текущие задачи и результаты остаются в SQLite. Формат YAML и HTTP API метаданных совместимы с прежними версиями; API продолжает принимать старые поля для существующих клиентов, пропущенные старые поля сохраняются, явные `current_focus: ""` / `next: []` очищают их.

Главная показывает проекты с целью, состоянием, текущими задачами и последней записью работы. Общие задачи собраны отдельно; каждая задача открывается по номеру. Очередь решений и сигналы внимания помогают выбрать следующее действие. Пять последних записей работы фильтруются по периоду; общая лента доступна через «Историю». Записи работы и commits не заменяют внешние действия проверок и не сбрасывают их отсчёт.

Проект определяется по известному основному каталогу или списку worktree, полученному Git **в зарегистрированном репозитории**. Worktree может быть вне корней сканирования. Если каталог неизвестен, связан с несколькими проектами, содержит неподдерживаемую ссылку или не совпадает с `projectId`, сервер отказывает. Git remote и название папки не используются для догадки.

MCP не предоставляет запуск команд, чтение произвольных файлов, удаление записей, изменение настроек или сканирование. Единственная Git-операция определения проекта — чтение списка worktree. Решения читаются существующим индексом только из настроенных источников и по его ключам. Это локальные права текущего пользователя, без удалённого сервера и OpenAI API. Описания задач, ссылки и решения не исполняются.

## Связь с Agent Engineering Kit

Изменения общих правил Kit для этого подключения не нужны. MCP задаёт инструменты и порядок работы с задачей; Kit продолжает определять разработку, проверки, язык и полномочия. Проект без MCP работает как раньше.

Предложение для отдельной задачи в Kit: добавить необязательный workflow работы с внешней доской. Он должен включаться только при доступных инструментах и разрешении владельца, передавать каталог текущей сессии, проверять проект, учитывать конфликты версий и отличать частичный результат от завершения. Языковые требования остаются в существующих CORE, DOCUMENTATION и PRODUCT. Проверка такого workflow должна отдельно подтвердить работу подключённого проекта и обычную работу без MCP. Репозиторий Kit эта реализация не меняет.


## Диалоги Codex как дополнительный контекст

Откройте ручной AI-анализ обзора недели/месяца и ссылку **Выбрать диалоги и сохранить краткий итог**. Для каждого проекта отдельно подтвердите чтение. Само разрешение не читает чаты. Затем проверьте CLI, откройте список и выберите содержательный диалог. Архивные диалоги выбираются отдельно. Наличие CLI или успешная проверка версии не подтверждает доступ к конкретной истории.

Поддерживается локальный Codex CLI `0.158.x` с `thread/list`, metadata-only `thread/read`, `thread/turns/list` и `thread/items/list`. По умолчанию используется `codex.exe` в Windows или `codex` в остальных системах. Оператор может задать `CONTROL_CENTER_CODEX_PATH` в окружении HTTP-процесса как путь к доверенному исполняемому CLI; аргументы или shell-команды из браузера не принимаются. Новая версия CLI требует проверки протокола. Отсутствие CLI, неподдерживаемый метод или история без item pagination показывают ошибку; задачи, обзоры и остальное приложение продолжают работать. Прямого чтения папок сессий или запасного полного архива нет.

Список читается из state DB (`useStateDbOnly: true`), без сканирования и восстановления JSONL-архива. Диалог должен сначала попасть в разрешённый список; произвольный ID не открывается. Пропущенная или устаревшая запись индекса не заменяется поиском по всем чатам. Список ограничен точными каталогами зарегистрированного проекта и его существующих Git worktree с проверенной общей Git directory. Путь через symlink, подкаталог, заменённый worktree и другой зарегистрированный проект не расширяют доступ. Новый набор worktree, изменение настроек приватного контекста или политики выборки требуют повторного подтверждения. По имени или remote диалог не сопоставляется. Источник, вернувший чужой cwd, отклоняется до чтения его текста.

За один просмотр проверяются до 50 последних обращений выбранного диалога; текст читается максимум у восьми обращений, до 50 items у каждого и 40 текстовых сообщений суммарно. Отбор за период основан на времени начала обращения; отдельный ответ мог появиться позже. Обращения без времени исключены и указаны отдельно. Текст user/assistant показан выдержками до 1000 UTF-8 байт без повреждения символов; сокращения и неполная выборка помечены. Командные items, tool output, reasoning и вложения не копируются. Обычный текст ассистента всё равно может пересказывать команды или содержать личные сведения: проверьте его вручную.

Напишите собственный краткий итог и отметьте до восьми нужных выдержек. Сохраняются только они, сведения об источнике и хэш обработанного текста; полный текст диалога не архивируется. На один обзор допускаются до двух итогов. Просмотр живёт в памяти 15 минут, до 20 просмотров одновременно. Сохранение повторно читает ограниченную выборку и проверяет её хэш, в том числе изменения после видимой части текста; потерянный ответ безопасно повторяется. Конкурирующая редакция требует обновления страницы, не перезаписывается автоматически.

**Проверить изменения диалога** явно перечитывает ту же ограниченную выборку. При изменении или недоступности источник помечается устаревшим. Автоматического наблюдения нет; хэш не подтверждает неизменность всего диалога или истинность сказанного. Для новой версии просмотрите текст заново и подтвердите новый итог. Выключение доступа прерывает активные чтения, очищает временные просмотры и запрещает включать старые итоги в новые AI-пакеты. При повторном разрешении прежние итоги нужно заново просмотреть. Уже сохранённые AI-отчёты остаются читаемыми.

Для отправки в OpenAI выберите точные итоги в **ручном** AI-анализе и отдельно подтвердите просмотр и отправку полного пакета. Разрешение читать Codex не разрешает платный вызов. AI-расписания итоги диалогов не используют и новые чаты не читают. После обновления политики старые неподтверждённые пакеты требуют подготовки заново, существующие расписания останавливаются до повторного включения; новый вид источника автоматически не добавляется.

Удаление итога удаляет его локальный текст и выдержки. Сохранённые AI-пакеты и принятые предложения сохраняют ранее утверждённые основания. После удаления проекта итоги доступны локально с прежней принадлежностью, но повторное чтение и отправка запрещены. Backup отключает разрешения в копии; для внешней raw-копии обязателен `--restore-recovery` до запуска процессов, как в [восстановлении данных](data.md). Обычный restart сохраняет актуальное разрешение; содержимое чатов при старте не читается.

Протокол: [официальная документация Codex App Server](https://learn.chatgpt.com/docs/app-server). Интеграция отправляет только initialize/initialized и перечисленные read-only методы, отклоняет входящие запросы разрешений, не вызывает thread/start/resume, turn/start, инструменты или команды из переписки. Одновременно разрешены не более двух чтений на HTTP-процесс и одно для проекта. Один процесс CLI ограничен 20 секундами RPC после проверки версии, 1 MiB на строку и 2 MiB stdout суммарно; диагностика CLI не попадает в HTTP или логи. Закрытие ждёт освобождения процесса.
